# Experiment execution and evaluation

## Setup

**Important:** some parts of the benchmark runner suite assume file paths specific to the devcontainer setup used during development. **To setup the project with the devcontainer please refer to the [general README](../README.md).** Otherwise, several modifications must be made:

- The implemented benchmarks suites - DaCapo and Barista - are by default expected to be available at `/data/dacapobench` and `/data/baristabench`. See the [devcontainer configuration](../.devcontainer/Dockerfile#L49-L66) for installation instructions. Either place the suites at their respective `/data` directories or add the `"context_path"` property to every benchmark configuration in [configs/benchmarks.json]() (note the `type`).
- The graal open source compiler location needs to be properly configured. By default the suite expects graal to be at `/workspace/graal/`. Change the compiler location in [benchmarks/compiler.py]() if this does not match your setup.

Create and activate the environment and install dependencies:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

## Experiment execution

To run an experiment, execute:

```bash
python3 run_benchmarks.py <path/to/config.json>
```

Upon completion, the runner reports metrics such as execution time, binary size, and compilation time in the standard output. The results are additionally saved to two CSV files located in `results/current/results.csv` and `results/current/compilation_results.csv` for the runtime performance and compilation results, respectively.

The table below lists all the configuration files that were used throughout the evaluation of the thesis. All config files are located in [configs/](configs). Configuration files not described in the table were used for preliminary experiments and testing, but not for the final evaluation and are only included for completeness.

|**Configuration file**|**Description**|
|-|-|
|[base-opts.json](configs/base-opts.json)|Compiles and runs the benchmarks repeatedly using the baseline optimization levels used throughout the study. We executed these once using this configuration file to save time on experimente execution with the other configuration files. We still include base optimization levels in the optimization's configuration files for completeness, but they were ran without them.|
|[generate-profile-data.json](configs/generate-profile-data.json)|Generates the profiling data by compiling and running a profiling build of every benchmark and writing the outputted profiling data to [results/current/profiling-data](). The directory is included to document the profiling data that was captured and used for all experiments in the thesis. Rerunning this configuration overrides these profiles.|
|[DII.json](configs/DII.json)|Uses the profiling data from [results/current/profiling-data]() to create a optimized builds using the DII optimization for all benchmarks. Performs 5 compilations for both DII in standalone mode (using only profiling data for the inlining) and in combined mode (falls back to the original trivial inlining implementation). The optimized binaries are then repeatedly ran. The resulting CSV files of the thesis' experiment execution were moved to [results/DII]().|
|[IC.json](configs/IC.json)|Uses the profiling data from [results/current/profiling-data]() to create a optimized builds using the IC optimization for all benchmarks with 5 repeated compilations. The binaries are then ran multiple times to minimize the impact of background noise. The resulting CSV files of the thesis' experiment execution were moved to [results/IC](results/IC).|
|[IC+DII.json](configs/IC+DII.json)|Uses the profiling data from [results/current/profiling-data]() to create a optimized builds by applying both the IC and DII optimizations. Performs 5 compilations for all benchmarks. The optimized binaries are then repeatedly ran. The resulting CSV files of the thesis' experiment execution were moved to [results/IC+DII]().|
|[gen-fingerprints-o3.json](configs/gen-fingerprints-o3.json)|Generates the fingerprints for the phase skipping optimization and writes them to separate text files for every benchmark in [results/current/skippable-phases]().|
|[phase-skipping-o3.json](configs/phase-skipping-o3.json)|Uses the fingerprints generated by the config above to perform phase skipping with the goal of reducing compilation time. Does not run the generated binaries, but repeatedly compiles the binaries to measure the compilation time distribution. The resulting CSV files of the thesis' experiment execution were moved to [results/phase-skipping]().|
|[get-invoke-counts.json](configs/get-invoke-counts.json)|Compiles every benchmark once with inline caching optimization flag enabled but does not execute it. The compilation is performed to generate log files with a `.count` filename that are used by the data analysis scripts since the logging when PGO is enabled includes statistics about the passed profile such as total call sites, virtual % invocations, etc.|

## Data analysis and plot generation

Below we detail which commands were used to obtain the data for every figure and table in the thesis. Plots are written as svg files to [results/plots]() and in some cases additionally write to the standard output for quick manual analysis used for quantitative commenting on the figures in the paper. The plots we generated for the thesis are also included in the [results/plots](results/plots) in the respective subdirectories for every experiment ([results/plots/DII](), [results/plots/IC](), [results/plots/IC+DII](), [results/plots/Phase skipping](results/plots/Phase%20skipping)).

The scripts are located in the [analysis_scripts](analysis_scripts) directory. Scripts that were used throughout the study for preliminary analysis but were not used to create the final data in the paper are included in [analysis_scripts/misc](analysis_scripts/misc).
